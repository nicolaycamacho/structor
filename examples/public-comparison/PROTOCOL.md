## Conditions and order

Run serially: **A baseline, A assisted, B assisted, B baseline**. This reverses
condition order across tasks without pretending to randomize or remove order
effects. Each root starts with identical consumer commits. Shared model weights
and evaluator learning remain confounders; agents receive no other attempt's
answer. Tools are not filesystem confinement: isolation is fresh conversation
plus a scoped workspace and explicit no-outside-read instruction. Disclose any
observed cross-read or injected parent context rather than hiding it.

Baseline: the task below, source, package scripts, existing smoke checks, local
AGENTS.md and README.md. Assisted: exactly the same plus a focused, Codex-only
harness generated by the pinned installed package, single-owner policy enabled,
hooks disabled, preserved local guidance and generated navigation. Append only
the checked-in `population-context.md` source map to ai/context.md. No proposed
implementation, task-specific answer, new fact or hidden check is added.
The map repeats source facts available to baseline, but its curation and the
extra reading instruction are treatment/briefing confounders. This pilot cannot
attribute effects to an individual first-batch feature.

Use this common briefing, replacing ROOT, TASK and CONDITION only:

> Work only within ROOT. Do not read outside it, other attempts, evaluator files,
> parent conversations or answer artifacts. This is an isolated coding attempt;
> do not delegate. Read repository guidance and relevant source. TASK.
> CONDITION. Use no network, installs or external services. Do not commit.
> You have 10 minutes and one attempt. Run the relevant existing npm test
> commands and any additional local checks you choose. Finish with files changed,
> inspected guidance, commands/results, remaining risks and questions. Do not
> write a separate report file.

## Acceptance and rubric

Acceptance source is frozen under evaluator/ and never copied to attempt roots.
After each attempt, run both consumer `npm test` commands and, from this example,
`node evaluator/acceptance.mjs A <workspace>` or `B <workspace>`. Retain command,
exit status, bounded stdout/stderr and final consumer diffs, including untracked
files. Verify the read-only consumer and harness against pre-attempt snapshots.
No browser check: these are plain data libraries with no UI surface.

Score independently, without a summed winner:

1. Correctness: 2 = smoke plus all task acceptance checks pass; 1 = existing
   smoke passes but task acceptance fails; 0 = regression or no executable result.
2. Convention fit: 2 = A reuses shared factory, B changes serializer and API
   schema together, and scope is respected; 1 = behavior passes but pattern or
   ownership has a repairable departure; 0 = read-only edits or broken contract.
3. Review corrections: count distinct required corrective changes after the
   first attempt, with exact rationale. Do not apply corrections to measured
   outcomes. Report suggested improvements separately from required fixes.
4. Effort: observed launch-to-final wall seconds and visible tool-call count;
   retain whether commands batch several actions. No inferred human time or
   token-cost claims. Record interruptions and unavailable metrics explicitly.
5. Setup friction: evaluator elapsed setup, commands, questions/decisions,
   preserved-guidance behavior, navigation and validation; separate this from
   coding time. No inference that a configured surface was actually read.

Report negative and inconclusive outcomes. n=1 per task/condition, no statistical
test, no causal or general speed claim. Keep structural validity, verified
knowledge, installation/adoption and observed effectiveness as four separate
evidence records using #137's date/scope/source/method/result/limitations fields.
Keep #123 open. Later merges from origin/main may update the artifacts delivery
branch, never the evaluated package, seed, protocol or measured attempts.
