# Observed results: synthetic public pilot

On 2026-11-13, both baseline and Structor-assisted attempts passed two small
tasks. No required post-attempt corrections were found. The assisted attempts
used more elapsed time and visible tool calls. **Effectiveness is inconclusive**:
this sample cannot establish a general improvement, regression or causal effect.

This completes the bounded observations for #147/#148, not #123's broader
multi-environment proof, launch or design-partner programme. No contract maturity
model or enforcement was implemented here.

## Setup effort and friction

The evaluator chose a focused, Codex-only harness, hooks disabled, with the
existing single-owner policy enabled. These are configuration choices, not
measurements of hook execution or ownership enforcement. No new client or paid
infrastructure was added. There were no unresolved questions or user assists.

The preparation/validation window from this evaluator session's start at
22:24:41 UTC to first attempt at 22:31:16 UTC was about 6 minutes 35 seconds.
That includes fixture authoring, preregistration, source/package validation,
rehearsal and materialization; it is not measured active human effort or a
general installation-time claim. The final materialization/setup subprocesses
were approximately 0.120 s baseline A, 0.854 s assisted A, 0.854 s assisted B and
0.097 s baseline B, excluding package work and rehearsals; timestamps are in the
condition manifests.

Two rehearsal failures were retained:

1. [Generation initially refused existing root guidance](evidence/a-assisted-setup.log).
   The evaluator supplied explicit `--preserve-existing-guidance` consent. This
   preserved each local AGENTS.md under its consumer's `.structor/preserved-guidance`
   and installed thin entrypoints; it did not merge or discard the local rules.
2. [The generated workspace check found its missing root pointer](evidence/a-assisted-rehearsal-bootstrap.log).
   The evaluator added the documented bootstrap preview/apply steps before
   checking the fresh measured workspaces. These rehearsal directories were
   never used for measured coding attempts.

The two final assisted setups each used the same sequence:

```sh
structor generate --config comparison.config.json --install-consumer-entrypoints --preserve-existing-guidance
cd example-platform-structor
# Append only population-context.md to ai/context.md before these checks.
node scripts/bootstrap-workspace.mjs --dry-run
node scripts/bootstrap-workspace.mjs
node scripts/validate-governance.mjs
node scripts/check-workspace.mjs
node scripts/check-readiness.mjs
```

Here `structor` is the offline-installed pinned CLI, never a fresh `npx` registry
resolution. [A setup](evidence/a-assisted-setup-success.log) and
[B setup](evidence/b-assisted-setup-success.log) passed every listed gate.
Generation preserved AGENTS.md only; there was no consumer CLAUDE.md to preserve.
READMEs stayed in place. Attempts sometimes probed nonexistent root README or
preserved README/manifest paths; those command failures remain in the traces.
They do not become hidden successful reads or additional whole-attempt retries.

The evaluator verified commands in both package.json files, two existing card
analogues and their helper, the API serializer/schema and frontend consumer.
The [population map](population-context.md) repeats those source facts without
an implementation answer. Navigation was generated as root AGENTS.md → ai/HUB.md
→ context/workflow plus consumer-local preserved guidance. Product-summary
starter content was left generic; this was a bounded map, not complete product
population. Generated readiness rows remained unassessed. The report below is
the separate observation record, not an automatic promotion of those rows.

## Confounders and next question

- Fresh conversations excluded parent history, other answers and acceptance
  source from briefings/materialized roots. Children still shared their parent
  runtime's system/developer guidance, tool catalog, general memories, model
  weights and initial artifacts-checkout directory. Tool access was broad.
  Explicit workdir/scope instructions and reviewed visible calls provide
  practical isolation; they do not establish OS confinement. No outside-root,
  cross-attempt or answer reads were observed in the retained calls.
- The same evaluator authored the synthetic tasks, source map, checks and
  scoring, and saw preceding answers. Serial order reversed conditions between
  tasks but did not randomize or blind them. No answer-derived briefing changes
  were made. Model/server state and hidden infrastructure effects are unknown.
- Assisted briefings explicitly requested harness reading and added a curated
  map. Baseline already had concise, relevant README guidance and obvious
  analogues. Reading overhead and this favorable baseline are plausible
  explanations for these timings; that is interpretation, not a measured cause.
  The study cannot isolate the contribution of routing, fit preparation, task
  validation, ownership policy or provenance features individually.
- Four short attempts on dependency-free data libraries cannot establish
  production usefulness, accuracy rates, cost savings or a performance guarantee.
  Token cost, active human effort, larger repositories, other models/clients,
  UI integration, contract maturity and sustained adoption were not measured.

The next supported question is whether the same fixed conditions help on a
larger, less obvious convention/boundary task where baseline sometimes needs
correction. A new study would need its own preregistration and stronger isolation
or blinding; this result is retained unchanged rather than rerun until favorable.
